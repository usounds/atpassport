# AtPassport 初期実装仕様

本ドキュメントは、AtPassportの初期開発における中核的な設計や規約を定義する「開発の羅針盤」です。ここに記載の仕様を正とし、実装を進めます。

## 1. システム概要 (System Overview)
AtPassportは、atprotoエコシステムにおいて、ユーザーに対してブラウザベースのセッション（UUID）を発行し、そこに複数のDID（およびハンドル）を紐付けて管理・解決するための汎用的なID管理プロバイダーとして機能します。

## 2. データストア方針
スケーラビリティとサーバーレスアーキテクチャへの親和性を考慮し、初期実装における主要データベースは **DynamoDB** とします。
※`GEMINI.md` に Prisma の記載がある場合でも、AtPassportのセッション・ID紐付け管理においては DynamoDB を優先して設計します。
データベースにおいては、UUIDに対して複数のハンドルを管理でき、かつ、プライマリーのハンドル塗装ではないハンドルを管理します。現時点では、すべてプライマリーとして取り扱います

## 3. 認証・セキュリティ (Authentication & Security)
- **UUIDの管理**: 
  - 発行されたUUIDは、`HttpOnly`, `Secure` 属性を持つ Cookie としてクライアントに保存されます。
  - セキュリティを担保するため、サーバー側の機密キーを用いてUUIDに対する**署名(Signed Cookie)**を行い、改ざんを防止します。
  - すべてのAPIリクエスト（および対象ページへのアクセス）において、Cookie内のUUIDとその署名の正当性を検証します。
  - UUIDは必ずユニークになるようにすること
- **有効期限 (TTL)**: 365日 (365 days)

## 4. APIエンドポイント詳細 (API Specification)
すべてのAPIリクエストは原則として **リダイレクト (302 Found)** で応答し、シームレスな画面遷移を実現します。

### 4.1. `/api/register`
ユーザーのハンドルを検証し、UUIDに紐付けるエンドポイント。
- **メソッド**: `GET`
- **パラメータ**: 
  - `handle`: 登録を試みるatprotoハンドル名
  - `callbackUrl`: 処理完了後に遷移させるコールバックURL
- **処理フロー**:
  1. Cookie内の署名付きUUIDを検証。未発行、または署名が無効な場合は、新規で生成したUUIDをCookieにセット(Set-Cookie)する。
  2. `atcute` のDoHリゾルバーを使用し、受け取った `handle` を解決（DIDを取得）する。
  3. **解決失敗時**: 404エラーと同等の扱いとし、データ保存は行わずに `callbackUrl` へそのままリダイレクトして戻す。
  4. **解決成功時**: 
     - 取得した `DID`、`handle`、および `UUID` を関連付けて DynamoDB に保存する（1つのUUIDに対して複数のDIDを紐付け可能とするデータ構造）。
     - `callbackUrl` の末尾（クエリパラメータ）に `?handle={handle}` を付与してリダイレクトする。

### 4.2. `/api/resolve`
外部アプリケーション等が、現在のセッション(UUID)に紐づくID情報を取得するためのエンドポイント。
（事前登録による `client_id` 管理等は不要とし、署名付きJWTを用いる構成を採用）
- **メソッド**: `GET`
- **パラメータ**: 
  - `callbackUrl`: 解決結果を付与してリダイレクトする先のURL
- **処理フロー**:
  1. Cookieから署名付きUUIDを検証する。存在しない・無効な場合は何も返さない状態でリダイレクトする。
  2. DynamoDBから、そのUUIDに紐づくプライマリーのハンドル・DID情報を取得する。
  3. 取得した結果を **JWT (JSON Web Token)** に格納し、AtPassport固有の秘密鍵でデジタル署名(RS256等)する。
  4. 署名済みJWTを、`callbackUrl` のクエリパラメータ `?token=<JWT>` として付与し、リダイレクトする。
  5. ※ 外部アプリーケーション側は公開されるAtPassportの公開鍵を用いてトークンを検証することで、セキュアにハンドルを受領する。

## 5. フロントエンド要件 (Frontend Requirements)
- **多言語対応 (i18n)**: JA (日本語) および EN (英語) のサポートを必須とする。
- **登録済みハンドルの表示**: 
  - 画面上には、現在のUUIDに紐づく登録済みハンドルの一覧を表示する。
  - その際、単なる文字列ではなく `public.api.bsky.app` の `getProfile` APIを用いて、アイコンや最新の表示名を取得し、リッチなUIで描写する。
- **データ管理UI**: 
  - ハンドルが未登録の場合は、登録できるようにする
  - 紐付けられたハンドルの削除は、このフロントエンドの管理画面上からのみ可能とする。
  - ユーザーが削除を実行した場合、DynamoDBから該当レコードを物理（または論理）削除する。

## 6. ライブラリ・依存関係 (Technology Stack)
- **Handle Resolution**: `@atcute/client` などのパッケージに内包される DoH リゾルバーを利用する。
